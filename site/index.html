      Pipeline

      Six checks, in this order.

      Every request walks the same six checks. Pick what happens to one and watch where it stops.

      1. 01 · ban

        Ban check

        Clients in a cooldown get a 429 before anything else runs.

      2. 02 · who

        Who is it

        The API key maps to a tenant and tier. No key means the anonymous tier, limited per client IP.

      3. 03 · cost

        Cost

        The longest matching route prefix sets the price. Unlisted routes cost 1.

      4. 04 · burst

        Burst

        GCRA enforces the per-second rate with a burst allowance.

      5. 05 · monthly

        Monthly

        The plan's units are spent only after burst passed.

      6. 06 · respond

        Headers or 429

        RateLimit-Limit, -Remaining and -Reset on every response. A block adds Retry-After and a JSON reason.

      outcome

      why

      Why burst comes first

      A request the burst limiter rejects never bills the plan; the reverse order would need a refund. A monthly reject does burn burst tokens, but those refill on their own.

      Quickstart

      Run it in front of your app.

      Three steps from nothing to a limited API with a live dashboard.

      1. 01

        Install

        Go, standard library only. One binary.

        terminal
        go install github.com/iammdzaidalam/limitplane/cmd/limitplane@latest
      2. 02

        Put it in front

        As a proxy, with Docker compose, or as Go middleware.

        One binary in front of any site. Dashboard at /_limitplane/.
        # demo app and dashboard on :8080
limitplane

# protect an existing site
limitplane --upstream http://localhost:3000

# your policy, limits shared through Redis
limitplane --upstream http://localhost:3000 \
  --config limitplane.example.json \
  --redis redis://localhost:6379
        The limiter and Redis, with your policy mounted in.
        # docker-compose.yml, trimmed from the repo's own
services:
  redis:
    image: redis:7-alpine
  origin:
    image: nginx:alpine
  limitplane:
    build: .
    command: ["--config", "/etc/limitplane/config.json",
              "--redis", "redis://redis:6379",
              "--upstream", "http://origin:80"]
    volumes:
      - ./limitplane.example.json:/etc/limitplane/config.json:ro
    ports: ["8080:8080"]
    depends_on: [redis, origin]
        Plain net/http middleware inside the module.
        // inside the limitplane module: the packages live under internal/
cfg, err := policy.Load("limitplane.example.json")
if err != nil { log.Fatal(err) }

gw := gateway.New(gateway.Config{
    Policy:  policy.NewStore(cfg),
    Limiter: limiter.NewLocal(),
    Quota:   limiter.NewLocalQuota(),
})
log.Fatal(http.ListenAndServe(":8080", gw.Middleware(mux)))
      3. 03

        Write the policy

        One JSON file. Edit it on disk or send SIGHUP: it is validated, then swapped in atomically, no restart. Unlisted routes cost 1.

        limitplane.example.json
        {
  "tiers": {
    "free": { "rate": { "limit": 5, "period": "1s", "burst": 10 },
              "monthly": 10000 },
    "pro":  { "rate": { "limit": 50, "period": "1s", "burst": 100 },
              "monthly": 1000000 }
  },
  "routes": [
    { "prefix": "/healthz",     "cost": 1 },
    { "prefix": "/v1/generate", "cost": 5 },
    { "prefix": "/v1/embed",    "cost": 2 }
  ],
  "keys": { "demo-free-key": { "id": "acme", "tier": "free" } },
  "anonymous": "free"
}

      Plans

      Three tiers, priced in units.

      These are the tiers in limitplane.example.json. A unit is what a route costs, so the same plan buys more health checks than AI calls.

      free

      5units / s · burst 10

      • 10,000 units a month
      • 2,000 AI calls or 10,000 health checks
      • Default for anonymous clients, per client IP
      Try free in the playground →
      pro

      50units / s · burst 100

      • 1,000,000 units a month
      • 200,000 AI calls
      • Alert at 80% of the plan
      • Per-tenant key, e.g. demo-pro-key
      Try pro in the playground →
      enterprise

      500units / s · burst 1,000

      • No monthly cap: leave monthly out of the tier
      • Burst limits and autopilot bans still apply
      • Add as many tiers and keys as you need
      • Hot-reloaded when the file changes
      See the config →

      Under the hood

      Small state, honest failure.

      gcra

      One int64 per key

      A token bucket needs a count and a refill time. GCRA keeps one number, the theoretical arrival time, so a check is one compare and one write: no float math, sharded in memory, zero allocations.

      // the check, trimmed from internal/limiter/rate.go
if tat < now { tat = now }
next := tat + cost*t            // t = time per unit
if next-burst*t > now {
    return blocked(retryAfter)  // tat is not stored
}
return allowed(next)
      redis

      One script

      The same algorithm runs as one Lua script that reads Redis TIME, so clock skew between replicas can't leak extra burst.

      replica A
      replica B
      →
      Lua + Redis TIME
      redis down

      Degrade, or fail closed

      A circuit breaker routes to the local limiter and marks each decision degraded. With --fail-closed you get a 503 instead.

      autopilot

      Bans and labels

      Bans a client after repeated burst blocks and labels clients human, bot, crawler or retry bug from request timing. A heuristic, not a model.

      20burst blocks
      10swindow
      5mban
      trust

      Trust nothing by default

      X-Forwarded-For counts only with --trust-proxy, and then only the right-most untrusted hop. Set --metrics-key in proxy mode: /metrics lists tenant ids.
