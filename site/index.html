LimitPlane How it works Quickstart GitHub

Rate limits priced by what a request costs.

LimitPlane is one Go binary you put in front of any HTTP service. A health check costs 1 unit, an AI call costs 5. Every tenant gets a per-second budget and a monthly cap, shared across replicas through Redis.

go install github.com/iammdzaidalam/limitplane/cmd/limitplane@latest
Get started Read the source

The idea

Count cost, not requests.

Most limiters treat every request the same, so a client can stay under "100 requests a second" while spending all of your GPU budget. LimitPlane gives each route a price and each tenant a budget in units. Cheap calls stay cheap. Expensive calls drain the bucket faster.

GET /healthz1 unit
GET /v1/search2 units
POST /v1/generate5 units

Request pipeline

Six steps, in this order.

  1. Ban check

    Clients in a cooldown get a 429 before anything else runs.

  2. Who is it

    The API key maps to a tenant and tier. No key means the anonymous tier, limited per client IP.

  3. Cost

    The longest matching route prefix sets the price. Unlisted routes cost 1.

  4. Monthly cap

    The plan's monthly units are checked first. No point rationing the speed of requests the plan can't pay for.

  5. Burst

    A GCRA limiter enforces the per-second rate with a burst allowance.

  6. Headers or 429

    RateLimit-Limit, -Remaining and -Reset on every response. Denials add Retry-After and a JSON body.

HTTP/1.1 429 Too Many Requests
RateLimit-Limit: 20
RateLimit-Remaining: 0
RateLimit-Reset: 3
Retry-After: 3

{"error":"rate_limited","reason":"burst","retryAfter":3,"message":"..."}

Quickstart

Run it in front of your app.

Point it at an upstream. The dashboard is served at /_limitplane/ on the same port.

# install
go install github.com/iammdzaidalam/limitplane/cmd/limitplane@latest

# proxy mode: meter everything going to :8080
limitplane --upstream http://localhost:8080

# shared limits across replicas
limitplane --upstream http://localhost:8080 --redis redis://localhost:6379

# no upstream: a demo app with /v1/ping and /v1/generate
limitplane

Policy is a JSON file. Edit it on disk or from the dashboard; changes swap in without a restart.

{
  "tiers": {
    "free": { "rate": { "limit": 10, "period": "1s", "burst": 20 }, "monthly": 50000 },
    "pro":  { "rate": { "limit": 100, "period": "1s", "burst": 200 } }
  },
  "routes": [{ "prefix": "/v1/generate", "cost": 5 }],
  "keys": { "sk_acme": { "id": "acme", "tier": "pro" } },
  "anonymous": "free"
}

Already writing Go? The gateway is plain net/http middleware.

gw := gateway.New(gateway.Config{
    Policy:  policy.NewStore(cfg),
    Limiter: limiter.NewLocal(),
    Quota:   limiter.NewLocalQuota(),
})
http.ListenAndServe(":8080", gw.Middleware(mux))

Under the hood

Small state, honest failure.

GCRA

Each key stores one timestamp, the theoretical arrival time. Allowing a request is one compare and one write. No token refill loop, no per-request timers.

Redis

With --redis, the check runs as one Lua script so concurrent replicas can't double-spend. The script is cached by SHA and reloaded if Redis restarts.

When Redis is down

Fails open to a local limiter by default and marks each decision as degraded, so you can see it. --fail-closed returns 503 instead.

Autopilot

Clients that keep hitting the burst limit get a short ban. Each client is labelled from its traffic pattern: human, bot, crawler, retry bug or warming up.
